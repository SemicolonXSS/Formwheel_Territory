# Formwheel Territory ⚔️

[게임](https://semicolonxss.github.io/Formwheel_Territory/) · [HUB](https://semicolonxss.github.io/Formwheel/)

## 모드
- 솔로 AI: 쉬움 / 보통 / 어려움 / 전문가 / 마스터 (기지 위협·영토 단절·상대 공격 예상 평가)
- 한 기기: 2명 또는 4명, 명령 제출 후 자동으로 다음 플레이어 차례
- 온라인 2인 / 4인: Firebase Realtime Database 방 코드 생성, 참여, 준비 후 방장 시작, 명령 동기화 (서버 규칙 배포와 실제 기기 테스트 필요)

## Territory 규칙
- 7x7 맵, 10~60턴 직접 입력(기본 20턴), 지도 3종
- 턴마다 확장, 공격 또는 방어. 온라인은 비밀 명령을 각자 제출
- 방어는 해당 턴 자신의 전체 영토를 보호. 공격을 실제로 막았다면 방어자는 연결된 중립 칸 1개를 무료 획득(가능한 칸이 있을 때), 공격자는 다음 턴 행동 불가
- 시작 시 각 플레이어 중심 기지(⌂) 하나 지급. 기지가 점령당하면 즉시 탈락
- 매 턴 상하좌우 연결을 기준으로 기지에 연결되지 않은 소유 영토는 중립화
- 마지막 생존자 승리 또는 최대 턴 종료 순간의 생존 영토 점수 1위 승리 (과거 최고 점수는 사용하지 않음)
- 중앙 별 지역은 3점, 일반 지역은 1점

## 운영 상태 및 주의사항
이 저장소의 온라인 코드는 클라이언트 주도 Firebase RTDB 프로토타입입니다. 현행 HUB 저장소의 `database.rules.json`은 기본 읽기·쓰기 차단이므로 별도 RTDB 규칙 설정을 하지 않았다면 방 만들기/참가에서 permission_denied가 납니다. Rules 파일을 GitHub에 커밋하는 것만으로 RTDB에 배포되지 않습니다.

**보안:** 현재 클라이언트에서 턴 해결을 실행하므로 조작 방지/랭킹/공식 대전에 사용하면 안 됩니다. 운영 배포 전에는 권한 제한된 Rules, Cloud Function의 서버 판정, 참가자 검증 및 재접속/동시 제출 테스트를 추가해야 합니다. 전역 read/write=true 규칙을 사용하지 마세요.

게임 화면은 HUB 로고 CSS와 파비콘을 활용합니다. 원격 배틀 UI가 나타나도 실제 서버 권한 및 인증 환경에 따라 동작이 제한될 수 있습니다.

## AI 공정성
솔로 모드에서 AI의 이번 턴 행동은 플레이어가 행동을 제출하기 전에 결정하고 보관합니다. AI는 비공개 플레이어 명령을 입력으로 사용하지 않습니다. 방어 평가에서는 상대가 현재 턴에 합법적으로 공격 가능한 칸만 계산하고 공격이 불가능한 상황의 방어는 피합니다.
